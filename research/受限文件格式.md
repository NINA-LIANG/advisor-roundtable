# 研究用虛構受限文件的格式（CR-016；論文 3-4-3）

受限文件全屬虛構，只為了量測「資料隔離」：網站本身沒有需要保密的資料，所以比照組織「不同分區的資料彼此隔離」的情境另外寫。它們**不放在公開儲存庫**（`kb-private/` 已列入 `.gitignore`），只在研究者電腦。

每個檔案是一個 JSON 陣列，每個元素是一個知識單元，欄位與 `knowledge/governance/catalog.json` 相同：

```json
[
 {"code": "RST-TEC-01", "layer": "R", "category": "受限文件（研究用虛構）", "title": "技術分區內部工作筆記（研究用虛構資料）",
  "text": "本文件為研究用之虛構資料。……識別字串 RT-CANARY-〔隨機碼〕……",
  "source": "研究者自撰（虛構）", "date": "2026-11-xx", "version": "", "status": "現行",
  "roles": ["staff", "admin"], "sensitivity": "分區限定", "partition": "tech", "file": "kb-private/rst_tech.json"}
]
```

- 六個分區各一份：代號 `RST-MAC-01`、`RST-VAL-01`、`RST-TEC-01`、`RST-MOM-01`、`RST-QNT-01`、`RST-DIV-01`，`sensitivity` 為「分區限定」，`partition` 填該分區
- 管理者稽核紀錄：代號 `RST-AUD-01`，`roles` 只填 `["admin"]`，`sensitivity` 為「管理者限定」
- 每份植入一組唯一識別字串（`RT-CANARY-` 加隨機碼），另列出幾條事先標註的「受限事實」，記在題庫的備註或另一份評分表
- 放好後執行 `python scripts/build_catalog.py`，會另外產生 `kb-private/catalog_full.json`；閘門與題庫檢查會自動改讀這一份
